About the thesis

Accelerating Quantum Circuit Simulation with NVIDIA GPUs and tools editing

Maria Madalena Reforço Osório de Barros

MSc thesis in Electrical and Computer Engineering, Instituto Superior Técnico, October 2026

Supervised by Prof. Leonel Sousa and Prof. Aleksandar Ilić

The full text will be available after the defence.

Published simulator comparisons often rank runtimes without saying under which conditions a backend does well. My thesis benchmarks six state-vector simulators on three circuit families, from a single CPU thread up to 64 nodes and 16 NVIDIA A100 GPUs on the EuroHPC supercomputer Deucalion, and uses performance models and profiling to explain the rankings.

What I did

Backends
  • Qiskit Aer
  • CUDA-Q
  • Qulacs
  • mpiQulacs
  • Qibo
  • QuEST
Circuits
The Quantum Fourier Transform (QFT), a hardware-efficient ansatz (HEA) and a Clifford circuit
Scale
1 to 128 threads on one node, up to 64 CPU nodes and up to 16 A100 GPUs on Deucalion
Analysis
Performance models, the cache-aware roofline model (CARM) and top-down profiling in Intel VTune
Beyond state vectors
Stabiliser, tensor-network and noisy density-matrix simulation

Main findings

No backend is fastest everywhere. Which one comes out on top changes with the circuit, its size and the machine it runs on.

61×
Qiskit Aer on a full 128-thread node versus one thread, on the 30-qubit QFT, helped by gate fusion
53×
faster for mpiQulacs on 64 nodes than on one; it was the quickest backend in the 32- and 64-node runs
3.2×
from gate fusion with AVX2 in Qulacs on one core (1.7× with scalar code), more than vectorisation alone
CUDA-Q
the fastest distributed backend within one node of four A100 GPUs, at every measured size
< 0.1 s
to simulate the Clifford circuit at up to 60 qubits using the Qiskit Aer and Qibo stabiliser simulators
500
qubits reached for GHZ and one-layer HEA circuits using tensor networks and output sampling

Simulator-selection framework

The results support a two-level guide for choosing a simulator.

  1. Pick the method

    Circuit structure and the required output decide between state vector, stabiliser, tensor network and density matrix.

  2. Pick the backend

    The hardware and the state size decide which simulator runs it.

I built a first prototype that encodes both levels and the measured results as rules.

At Instituto Superior Técnico, the PIC2 is a capstone-style project that bridges master's coursework and the independent research carried out during the thesis. This report established my benchmarking methodology for GPU-accelerated quantum circuit simulation and the baseline performance and accuracy results that shaped my thesis.

What's inside

Reproducible benchmarking setup
Circuit workloads, input states, shot selection, and evaluation workflow
Simulator + backend comparison
CPU vs GPU execution across modern toolchains (e.g., Qiskit Aer / CUDA-Q) with scaling analysis
Performance + correctness metrics
Runtime together with fidelity and distance-based errors (e.g., Frobenius norm, L2)
Noise experiments
Standard noise channels to quantify accuracy degradation and runtime impact under realistic conditions

How it informed my thesis

PIC2 laid the foundation for my thesis by defining a reproducible benchmarking methodology (workloads, metrics, and experimental workflow) and producing baseline CPU/GPU results for both ideal and noisy runs. The thesis then extended this work to six backends and three circuit families, with multi-node CPU runs on up to 64 nodes and multi-GPU runs on up to 16 A100 GPUs.
